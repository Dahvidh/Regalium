# C-01: Incorrect Reward Pool Accounting

**Severity:** Critical

**Contract:** Staking.sol

## Description

The staking contract calculates available rewards using:

```solidity
uint256 poolBalance =
    token.balanceOf(address(this))
    - stakedBalances[user];
````

The calculation only excludes the current user's stake.

It does not exclude all users' staked balances.

## Impact

Example:

```
Alice stake: 500 RGLM
Bob stake:   500 RGLM

Contract balance:
1200 RGLM
```

Actual reward pool:

```
1200 - 1000 = 200 RGLM
```

Current implementation:

```
1200 - Alice stake
= 700 RGLM
```

Alice may receive rewards funded by Bob's deposited tokens.

This can permanently reduce user staking balances.

---

## Remediation

Add a global staking counter.

### Add variable:

```solidity
uint256 public totalStaked;
```

### Update stake():

```solidity
totalStaked += amount;
```

### Update unstake():

```solidity
totalStaked -= amount;
```

### Replace:

```solidity
uint256 poolBalance =
    token.balanceOf(address(this))
    - stakedBalances[user];
```

With:

```solidity
uint256 poolBalance =
    token.balanceOf(address(this))
    - totalStaked;
```

# C-02: Accrued Rewards Can Be Lost

**Severity:** Critical

**Contract:** Staking.sol

## Description

The claim function resets timestamps regardless of whether rewards were successfully transferred.

Current code:

```solidity
_claimReward(msg.sender);
stakeTimestamps[msg.sender] = block.timestamp;
```

If the reward pool is empty:

* reward transfer fails silently
* timestamp resets
* accumulated rewards disappear

---

## Impact

Users permanently lose earned rewards.

---

## Remediation

Change `_claimReward()` to return whether payment succeeded.

Example:

```solidity
function _claimReward(address user)
internal
returns(bool)
{
    uint256 reward = calculateReward(user);

    if(reward == 0)
        return false;

    uint256 poolBalance =
        token.balanceOf(address(this))
        - totalStaked;

    require(
        poolBalance >= reward,
        "Insufficient rewards"
    );

    token.safeTransfer(user,reward);

    return true;
}
```

Update claim:

```solidity
function claimReward() external {

    bool paid = _claimReward(msg.sender);

    require(
        paid,
        "No reward available"
    );

    stakeTimestamps[msg.sender]
        = block.timestamp;
}
```

# H-01: Unsustainable Reward Emission Rate

**Severity:** High

**Contract:** Staking.sol

## Description

Current configuration:

```solidity
rewardRatePerSecond = 1e16;
```

Results:

```
100 RGLM stake
=
1 RGLM reward every second
```

Annualized:

```
31,536,000 RGLM per 100 tokens staked
```

---

## Impact

* Reward pool drains quickly
* Token economy becomes unstable

---

## Remediation

Use APR-based rewards.

Example:

```solidity
uint256 public rewardAPR = 20;
```

Calculation:

```solidity
reward =
(
    amount *
    rewardAPR *
    duration
)
/
(
    365 days *
    100
);
```

This gives predictable annual rewards.

---

# H-02: GameStore Creates Unbacked Rewards

**Severity:** High

**Contract:** GameStore.sol

## Description

Rewards are assigned without checking available funds.

```solidity
rewards[user] += amount;
```

---

## Impact

Players may have balances they cannot withdraw.

---

## Remediation

Track liabilities:

```solidity
uint256 public totalRewardsOwed;
```

When assigning:

```solidity
require(
    token.balanceOf(address(this))
    >= totalRewardsOwed + amount,
    "Insufficient reward funds"
);

totalRewardsOwed += amount;
```

When withdrawing:

```solidity
totalRewardsOwed -= amount;
```

# H-03: Presale Decimal Handling

**Severity:** High

**Contract:** Presale.sol

## Description

Current:

```solidity
tokenAmount = msg.value * rate;
```

Assumes RGLM has 18 decimals.

---

## Impact

Wrong token distribution if decimals differ.

---

## Remediation

Normalize using decimals:

```solidity
uint8 decimals =
IERC20Metadata(address(token))
.decimals();

uint256 tokenAmount =
(
msg.value *
rate *
10**decimals
)
/1 ether;
```

**Severity:** High

**Contract:** RegaliumToken.sol

## Description

Oracle response is not validated.

Missing:

## Remediation

(
,

,
,

With:

(

,

# M-01: Staking and Rewards Share Same Token Balance

**Severity:** Medium

## Problem

User deposits and reward reserves are mixed.

---

## Fix

Maintain separate reward accounting:

```solidity
uint256 public rewardReserve;
```

Only rewardReserve tokens can be distributed.

---

# M-02: Entire Supply Goes to Deployer

**Severity:** Medium

## Problem

Constructor:

```solidity
_mint(msg.sender, MAX_SUPPLY);
```

One wallet receives 100% supply.

---

## Fix

Use allocation contracts:

Example:

```
40% Treasury
20% Presale
20% Rewards
10% Team Vesting
10% Liquidity
```

Implement vesting contracts for locked allocations.

# M-03: Duplicate Exchange Rate Definitions

**Severity:** Medium

## Problem

Token:

```solidity
MATIC_TO_RGLM = 2;
```

Presale:

```solidity
rate = 2;
```

---

## Fix

Create one pricing contract:

```solidity
interface IPriceConfig {

function getRate()
external
view
returns(uint256);

}
```

All contracts reference the same source.

Before deployment:

1. Fix staking reward accounting.

1. Add pause functionality.
2. Add event logging.
3. Add presale limits.
4. Add vesting contracts.
5. Centralize protocol parameters.
